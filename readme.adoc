= Z80 simple computer
:toc:
:toclevels: 2

The schematic is the rebuilt sheet. It opens, it uses stock KiCad 10.0.7 symbols, and the parts now sit inside the paper. The notes under `docs/` say how that was done.

The PCB file in this directory is not the posted board. That file would not open, and it is kept unchanged in `as-posted/`. The project board is a new KiCad 10 board. The signal tracks from the first routing attempt have been removed. What is on it now is the Eurocard outline, the parts placed on the top, four layers, and the inner ground and +5V planes. The DE9 plug hangs off the left edge. There are no signal tracks.

The choices for this trial are in the plan. The sheet is A3, because the DIP-40 symbols do not fit A4. The board is a 160 by 100 mm Eurocard, four layers, a screw terminal for +5V, four M3 holes, and tracks written into the board file. FreeRouting was not used.

What is left:

. Route the signals. Not with the 0.25 mm grid script.
. Look at the placement in KiCad before that route.

`tools/build_schematic.py` rewrites the schematic. If you move a part in KiCad and then run that script, the script wins. Either edit in KiCad and stop using the script, or change the script. Do not do both.

== Previewing these notes

For a formatted view in Chrome or Chromium, install
https://chromewebstore.google.com/detail/asciidoctorjs-live-previe/iaalpfgpbocpdfblpnhhgllgbdbchmia[Asciidoctor.js Live Preview].
Enable *Allow access to file URLs* on the extension's details page, then open a local `.adoc` file.
The https://docs.asciidoctor.org/browser-extension/install/[installation notes] also mention Edge. Edge has not been tried here.

The two files in this directory are the Mixworx preview style used by the other local projects. Select them in the extension options:

* link:asciidoctorjs-crx-mixworx.css[asciidoctorjs-crx-mixworx.css]: stylesheet for type, headings, tables, code, and print.
* link:asciidoctorjs-crx-mixworx.js[asciidoctorjs-crx-mixworx.js]: run this *after the document has been rendered*. It marks modifier keys, splits a heading at the first prose colon, and puts anchor positions back after rendering.

If the repository moves, or either file changes, select them again in the extension options.
GitHub itself still shows the normal colon in a heading. The line break is only in this local preview.
